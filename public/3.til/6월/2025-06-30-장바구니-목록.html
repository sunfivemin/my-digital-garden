📍 주제 1: 장바구니 목록 렌더링 및 체크박스 상태 관리

  • 각 장바구니 아이템(CartItem)은 체크박스를 가지고 있고,
  • checkedItems: number[] 배열로 선택된 항목을 관리한다.
  • useMemo를 활용해 선택된 항목만 기준으로 총 수량과 총 금액을 계산한다.
const totalQuantity = useMemo(() =>
  carts.reduce((acc, cart) =>
    checkedItems.includes(cart.id) ? acc + cart.quantity : acc, 0), [carts, checkedItems]);

const totalPrice = useMemo(() =>
  carts.reduce((acc, cart) =>
    checkedItems.includes(cart.id) ? acc + cart.price * cart.quantity : acc, 0), [carts, checkedItems]);

📍 주제 2: 삭제 버튼 클릭 시 확인 모달 띄우기

  • CartItem 내부에서 삭제 버튼 클릭 시 커스텀 모달을 띄우고, 확인을 누르면 onDelete(cart.id) 콜백을 실행함.
  • 모달은 컴포넌트를 활용해 다크 백드롭 + 컨펌 UI 제공.
<Button intent="danger" onClick={() => setOpen(true)}>장바구니 삭제</Button>

<Modal open={open}>
  <p>정말 삭제하시겠습니까?</p>
  <Button onClick={handleDeleteConfirm}>삭제</Button>
</Modal>

📍 주제 3: 주문 요약 UI 및 주문하기 기능

  • 우측 사이드에 주문 요약 카드(CartSummary)를 배치.
  • 선택된 항목 기준으로 총 수량 / 총 금액 표시.
  • “주문하기” 버튼 클릭 시 확인 모달을 띄운 뒤, 상태 기반으로 주문 페이지(/order)로 이동.
<Button onClick={handleOrder}>주문하기</Button>

<Modal open={isModalOpen}>
  <p>선택한 상품을 주문하시겠습니까?</p>
  <Button onClick={handleOrderConfirm}>주문</Button>
</Modal>

📍 주제 4: UX 개선 - 항목 미선택 시 Toast 알림

  • 아무 항목도 선택하지 않고 “주문하기”를 누를 경우, 모달 대신 토스트 알림을 사용해 간결한 피드백 제공.
  • react-hot-toast 라이브러리를 사용.
if (checkedItems.length === 0) {
  toast.error('주문할 상품을 선택해주세요.');
  return;
}

📍 주제 5: 주문서 작성 페이지 흐름

  • Cart 페이지에서 선택된 장바구니 항목 데이터를 navigate('/order', { state })로 전달함.

  • 전달되는 데이터는 OrderSheet 타입에서 delivery를 제외한 Omit<OrderSheet, 'delivery'> 형태.

  • Order 페이지에서는 유저 입력을 기반으로 delivery 정보를 수집하고, 이를 결합해 최종 OrderSheet로 완성.

  • 주소 입력은 다음 우편번호 API를 script 로드 방식으로 처리하고, 완료 시 setValue로 react-hook-form 내부 상태를 갱신.

  • 결제 버튼 클릭 시:
    - 1단계: 확인 모달("주문을 진행하시겠습니까?") 표시
    - 2단계: 확인 버튼 클릭 시 주문 API 호출
    - 3단계: 성공 시 알림 모달("주문이 완료되었습니다!") 표시 후 /orderList로 리디렉션

const orderData: OrderSheet = {
  ...orderDataFromCart,
  delivery: {
    address: `${data.address} ${data.addressDetail}`,
    receiver: data.receiver,
    contact: data.contact,
  },
};
await order(orderData); // 주문 API 요청
  • 이 과정에서 사용자의 토큰이 없거나 만료된 경우 /login으로 리디렉션되어 인증을 보장함.

💭 회고

• 새롭게 알게 된 점  
→ 상태 기반으로 모달 UI를 구성하고, 선택된 항목만을 대상으로 데이터를 구성하여 navigate('/order', { state })로 전달하는 흐름이 유용하다는 것을 알게 되었다.  
→ Zustand와 같은 전역 상태 관리 도구를 사용할 때도 필요한 부분만 모듈화해서 사용할 수 있다는 점이 인상 깊었다.  

• 어렵게 느껴졌던 부분  
→ 장바구니 아이템 삭제 후 상태 갱신 타이밍과 UI 반영이 어색하게 느껴졌고, 비동기 흐름에 따라 삭제 이후 렌더링 순서를 명확히 조절해야 했다.  
→ 또한, 주문 데이터 전달 과정에서 OrderSheet 타입을 명확하게 정의하고 delivery 없이 넘기는 Omit 활용이 처음에는 헷갈렸다.
