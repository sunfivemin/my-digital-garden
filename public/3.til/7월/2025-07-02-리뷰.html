📍 주제 1: MSW  활용한 API 응답 Mocking

✅ 왜 MSW를 사용했나?

  • 백엔드 서버 개발이 완료되지 않은 상태에서도 프론트엔드 작업을 빠르게 진행할 수 있게 하기 위함
  • 실제 브라우저에서의 요청 흐름과 가장 유사한 방식으로 mock 처리 가능 (XHR/fetch 캡처)
  • storybook, testing 환경뿐 아니라 실제 개발 중에도 유용함

📦 설치 및 기본 구성

npm install msw --save-dev

public/mockServiceWorker.js는 아래 명령어로 설치됨:

npx msw init public/ --save

🧩 API 핸들러 작성 예시 (src/mock/review.ts)

import { HttpResponse, http } from 'msw';
import type { BookReviewItem } from '@/models/book.model';

export const reviewsById = http.get('/reviews/:bookId', ({ params }) => {
  const { bookId } = params;

  const mockData: Record<string, BookReviewItem[]> = {
    '1': [
      {
        id: 1,
        userName: '홍길동',
        content: '아주 재밌어요!',
        createdAt: '2025-07-01T12:00:00Z',
        score: 5,
      },
    ],
    '2': [
      {
        id: 2,
        userName: '김철수',
        content: '깔끔한 구성이 좋았어요.',
        createdAt: '2025-07-05T15:30:00Z',
        score: 4,
      },
    ],
  };

  const data = mockData[bookId as string] || [];
  return HttpResponse.json(data);
});

🔗 핸들러 등록 (src/mock/browser.ts)

import { setupWorker } from 'msw/browser';
import { reviewsById } from './review';

export const worker = setupWorker(reviewsById);

🚀 main 엔트리에서 활성화 (main.tsx 또는 index.tsx)

if (import.meta.env.MODE === 'development') {
  const { worker } = await import('./mock/browser');
  worker.start();
}

❗️실수했던 포인트

  • GET /reviews/1 요청이 404 Not Found로 계속 실패
  • 문제 원인: 핸들러 경로는 /reviews/:bookId였지만, 실제 요청은 http://localhost:9999/reviews/1
  • MSW는 service worker이므로 도메인을 기준으로 동작, 즉 baseURL이 localhost:9999면 경로도 localhost:9999/reviews/:id여야 함
  • 하지만 MSW는 실제 API 요청을 가로채는 방식이므로 baseURL 없이 상대 경로만 일치하면 동작함 → 해결: baseURL 설정은 유지하되 핸들러는 /reviews/:bookId로만 작성

📍 주제 2: faker.js + MSW로 실전형 리뷰 데이터 모킹하기

✅ faker와 MSW가 필요한 이유

개발 초기에는 API가 아직 없거나, 불완전할 수 있습니다.
이럴 때 UI 개발과 테스트를 먼저 진행할 수 있도록 MSW(Mock Service Worker)와 faker.js를 조합해 더미 데이터를 구성할 수 있습니다.

✅ 목표

  • 📦 GET /reviews/:bookId 요청이 들어오면
  • 🔄 faker.js로 실감 나는 가짜 리뷰 데이터를 생성하고
  • ✅ MSW가 브라우저 상에서 응답을 대신 처리

✅ 구현 코드

// src/mock/review.ts
import { HttpResponse, http } from 'msw';
import { faker } from '@faker-js/faker';
import type { BookReviewItem } from '@/models/book.model';

// 📌 bookId 별로 가짜 리뷰 3개 생성
const generateMockReviews = (bookId: string, count = 3): BookReviewItem[] => {
  return Array.from({ length: count }).map((_, index) => ({
    id: index + 1,
    userName: faker.person.fullName(),
    content: faker.lorem.sentence(),
    createdAt: faker.date.recent({ days: 10 }).toISOString(),
    score: faker.number.int({ min: 1, max: 5 }),
  }));
};

// 📌 MSW 핸들러 정의
export const reviewsById = http.get(
  'http://localhost:9999/reviews/:bookId',
  ({ params }) => {
    const { bookId } = params;
    const data = generateMockReviews(bookId as string);
    return HttpResponse.json(data);
  }
);
단계 설명
1 /reviews/:bookId 요청이 발생하면
2 params.bookId를 기준으로
3 faker가 리뷰 count개를 생성
4 HttpResponse.json(data)로 응답 처리
  • faker.person.fullName() → 무작위 이름
  • faker.lorem.sentence() → 랜덤 리뷰 내용
  • faker.date.recent({ days: 10 }) → 최근 10일 내 날짜
  • faker.number.int({ min: 1, max: 5 }) → 1~5점 평점

💭 회고

• 새롭게 알게 된 점

  • MSW는 단순한 테스트 도구가 아니라, 프론트 개발 단계에서도 아주 유용한 mock 서버 역할을 한다
  • http.get('/reviews/:bookId')는 도메인을 무시하고 경로만 일치하면 가로챌 수 있다
  • setupWorker는 브라우저 기반 환경에서만 동작하며, 테스트에서는 setupServer 사용 필요
  • faker.js와 MSW를 함께 쓰면 백엔드 없이도 실제와 유사한 응답 흐름을 구현할 수 있다는 점이 인상적이었다.
  • 특히 params 기반으로 데이터를 유동적으로 만들어내면, 하나의 핸들러로 다양한 테스트가 가능하다는 점이 유용하다.

• 어렵게 느껴졌던 부분

  • 처음엔 http.get('/reviews/:bookId')처럼 상대경로로 하면 매칭이 안 되는 문제가 있어 "http://localhost:9999/reviews/:bookId"처럼 절대경로로 명시해야 정상 작동했다.
