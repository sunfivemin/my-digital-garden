📍 주제 1: 🧭 배너(Banner) 데이터 흐름 구조 설명

✅ 1. 목적

배너 영역에서 사용하는 데이터를 Mock 데이터(MSW) 기반으로 불러오고, 이를 useMain 훅에서 통합적으로 가져와 메인 페이지에 렌더링하는 구조를 구현

✅ 2. 전체 흐름 요약

[Mock Data 정의 (banners.ts)]
     ↓
[Mock Service Worker 핸들러 등록 (browser.ts)]
     ↓
[axios 기반 fetch 함수 정의 (banner.api.ts)]
     ↓
[useMain 훅에서 fetch → 상태 저장]
     ↓
[컴포넌트에서 useMain() → 배너 사용]

✅ 3. 코드 흐름 상세

📁 /src/mock/banners.ts

  • MSW로 가짜 데이터를 정의하고, /banners 엔드포인트 응답을 가로채서 응답을 반환함
export const fetchBanners = async (): Promise<Banner[]> => {
  return await requestHandler<undefined, Banner[]>('get', '/banners');
};

📁  /src/api/banner.api.ts

  • axios 기반 API 함수인 fetchBanners를 정의
  • 내부적으로는 requestHandler 유틸을 사용
export const fetchBanners = async (): Promise<Banner[]> => {
  return await requestHandler<undefined, Banner[]>('get', '/banners');
};

※ requestHandler는 axios를 래핑한 유틸 함수

📁 /src/hooks/useMain.ts

  • 메인 페이지에서 필요한 모든 초기 데이터(배너, 신간, 리뷰 등)를 가져오는 커스텀 훅
const [banners, setBanners] = useState<Banner[]>([]);

useEffect(() => {
  fetchBanners().then(setBanners);
}, []);

✅ 4. 데이터 흐름 정리

단계 설명
① Mock 핸들러 정의 /banners 요청을 가로채고 가짜 데이터 응답
② MSW 등록 핸들러를 setupWorker에 연결
③ API 요청 함수 작성 fetchBanners()에서 axios 요청
④ 커스텀 훅 사용 useMain()에서 데이터를 불러오고 상태 저장
⑤ 컴포넌트 사용 메인 화면에서 banners.map(...) 형태로 UI 렌더링
  • MSW는 백엔드 없이도 API 개발과 테스트가 가능하도록 도와주는 도구입니다.
  • 실제 API처럼 동작하는 핸들러를 만들고, 이를 기반으로 axios를 통해 데이터 요청을 처리합니다.
  • 모든 데이터는 useMain 훅에서 한 번에 가져와, 컴포넌트에서는 비즈니스 로직 없이 상태만 받아 사용할 수 있습니다.
  • 테스트, 개발, 분리된 레이어 설계에 적합한 구조입니다.

✅ 마무리

이런 구조를 통해 API 개발이 지연되거나 불완전한 상황에서도 프론트 개발을 병렬적으로 진행할 수 있고,
이후 실제 API로 교체할 때는 fetch 함수만 바꿔주면 되기 때문에 유지보수에도 유리한 구조입니다.
