🌐 오픈소스 라이선스 제대로 이해하기

✅ 오픈소스 라이선스란?

오픈소스로 배포/공개된 소스 코드를 사용할 때 따라야 하는 규칙 및 조건을 명시한 법적 장치입니다.
단순히 코드를 '공개'했다고 해서 누구나 자유롭게 사용할 수 있는 것은 아니며, 라이선스 조항을 반드시 따라야 합니다.

예시:

  • React → MIT License
  • Apache Tomcat → Apache License 2.0

❗ 라이선스를 지키지 않으면?

  • 아무 표시 없이 public repo 코드를 무단으로 사용하면 저작권 침해입니다.
  • 개인/기업 모두 법적 분쟁 위험이 있으니 반드시 주의해야 합니다.

📚 주요 오픈소스 라이선스 종류

✨ 이미 널리 사용되는 오픈소스 라이선스를 참고해서 사용하는 것이 좋습니다.

라이선스 특징 예시
MIT 사용, 수정, 배포 모두 자유 / 출처만 명시하면 됨 React, TailwindCSS, jQuery
GPL 배포 시 전체 소스 공개 의무 / 2차 저작물도 GPL 적용 Linux, Git, WordPress
Apache 2.0 사용 자유 / 단, NOTICE 파일 & 라이선스 명시 필요 Android, Apache 서버
BSD MIT와 유사 / 조건 거의 없음 / 특정 기관 명시 필요 FreeBSD, XNU
AGPL GPL보다 강력 / 네트워크 상 공개도 포함 MongoDB 등

▶ GPL (General Public License)

  • Free Software Foundation
  • 목적: 코드 사용/배포 시 반드시 소스 코드 공개 요구
  • 예: Linux, Git, Firefox, WordPress 등
  • ➤ AGPL은 서버 앱도 공개 필요

▶ MIT

  • 조건이 매우 자유롭고 사용/배포/변경 자유 ✔
  • 단, 라이선스 명시 필수
  • 예: React, Angular, Bootstrap 등

▶ Apache

  • license.txt 내 조건 명시 필요
  • 버전 2.0 이상 권장 / notice.txt나 copyright.txt 포함
  • 예: Android

▶ BSD

  • MIT와 비슷하게 매우 자유로우며, 명시만 하면 사용 ✔
  • 예: Berkeley Software Distribution

📝 오픈소스 라이선스 표기 방법

오픈소스를 사용할 때는 다음 정보를 반드시 명시해야 합니다:

  • 오픈소스명
  • 공식 홈페이지 주소 (링크)
  • 라이선스 종류/이름
  • 라이선스 전문 (공식 문서 링크 등)

예시

- React  
  - https://reactjs.org  
  - MIT License  
  - https://opensource.org/licenses/MIT

📦 실제 사용 예시 (npm 기반 라이브러리)

npm 패키지를 사용할 경우, 대부분 package.json에 아래처럼 명시되어 있습니다:

"license": "MIT"

또는 npmjs.com에서도 라이선스를 직접 확인할 수 있습니다.

📌 한국의 공인된 라이선스 검색 플랫폼: OLIS
-> 라이선스 분류 > OSI 라이선스 메뉴를 참고하세요.

❓ 오픈소스 라이선스, 왜 중요한가요?

  • ✔️ 사용 범위를 명확히 알 수 있어 리스크를 줄일 수 있음
  • ⚠️ 무단 사용 시 저작권 침해 및 법적 책임 가능성
  • 💡 오픈소스를 존중하는 개발 문화에 기여

✅ 요약 체크리스트

  • 사용한 오픈소스의 라이선스 종류 확인
  • README or NOTICE에 명시
  • 상용 서비스 적용 시, 제약 조건 확인 (특히 GPL 계열)
  • 커뮤니티/기여 규칙도 함께 확인
