🚀 배포-인도 자동화와 컨테이너 기반 파이프라인 구축 정리

🧩 1. 전통적인 인도 프로세스의 한계

  • 느린 인도 기간: 요구사항 정의부터 제품 전달까지 긴 시간 소요
  • 느린 피드백 주기: 개발팀 효율성 저하
  • 자동화 미비: 릴리스 예측 어려움
  • 핫픽스 위험성: 급한 수정에 테스트 부족
  • 개발문화 건전성 제한: 팀 스트레스, 책임 분산, 낮은 만족도

🔁 2. 해결책: 지속적 인도 및 배포 자동화

핵심 질문

  • 단 1줄 변경도 얼마나 빨리 배포할 수 있는가?
  • 이 작업을 반복 가능하고 안정적으로 할 수 있는가?

해법

  • 프로세스의 각 단계를 자동화
  • 빠른 인도 + 짧은 피드백 루프
  • 반복 가능한 릴리스와 롤백
  • 유연한 릴리스 정책 가능

Git과 연계

  • Git의 논리적 연관성 있는 커밋 → 자동화 연결

🔄 3. 자동 배포 파이프라인 단계 요약

[코드 변경] → [지속적 통합] → [자동 인수 테스트] → [구성 관리]

  • 지속적 통합 (CI)

    • 빌드 및 단위 테스트 자동 수행
    • 정적 분석 → 코드 품질 체크
    • 커버리지 리포트 생성 등

  • 자동 인수 테스트 (UAT)

    • 고객 요구사항 충족 여부 검증
    • QA, 통합 테스트, 비기능(성능/보안 등)

  • 구성 관리 (CM)

    • 환경/소프트웨어 변화 추적 및 제어
    • 배포 버전 관리, 도구 설치 자동화

🔧 4. CD를 위한 기술적 전제조건

  • 자동화된 빌드/테스트/배포/패키징
  • 빠른 파이프라인 실행 (커밋 → 결과까지 짧게)
  • 장애 시 롤백 가능성 확보
  • 무중단 배포 (다운타임 최소화)
  • 트렁크 기반 개발 방식 적용

🐳 5. 웹 개발 파이프라인 구성 도구 정리

🔨 핵심 자동화 도구

역할 도구
컨테이너 & 클러스터 Docker, Kubernetes
파이프라인 자동화 서버 Jenkins
구성 관리 Ansible
버전 관리 GitHub

이 외에도 정적 분석 도구, 테스트 프레임워크 등 다양

🔍 몇 가지 의문 해소

  • ❓ 도구를 모두 익혀야 하나요? → ❗도구보다 환경 설정 이해가 중요
  • ❓ 도구 사용법이 제일 중요한가요? → ❗각 도구가 맡은 프로세스의 역할을 이해하는 것이 더 핵심
  • ❓ 소개된 도구는 필수인가요? → ❗아님. 유사 역할 도구 많음 (유연하게 선택)

🧱 6. 컨테이너와 Docker 핵심 개념

🧊 가상화와 컨테이너 비교

항목 VM Docker 컨테이너
실행 환경 하드웨어 모사 (Hypervisor) 운영체제 위에서 경량 실행
격리 방식 완전한 VM 프로세스 수준 격리 (샌드박스)
무게감 무거움 매우 가벼움 (빠른 실행)

🔄 Docker 컨테이너 구조

  • Docker Image: 상태 없는 계층 구조, 실행을 위한 정적인 파일 묶음

    • 버전 지정 가능, 공유 및 전송 가능

  • Docker Container: 이미지 실행 인스턴스, 상태를 가짐

    • 여러 개 생성 가능 (서로 독립)
docker run <image-name> # 이미지로 컨테이너 실행
docker ps -a             # 현재 실행 중 또는 종료된 컨테이너 목록

🧪 Docker 명령어 요약

docker images              # 이미지 목록 확인
docker stop <container>   # 컨테이너 실행 중지
docker rm <container>     # 컨테이너 삭제
docker rmi <image>        # 이미지 삭제

🧱 Docker의 실제 동작 흐름

⛓️ 이미지와 컨테이너

  • 이미지 → 계층(Layer) 기반 구조
  • Web App → Nginx 기반 → Ubuntu 기반 → Docker 이미지로 구성
  • 하나의 이미지로 여러 컨테이너 실행 가능

🔁 이미지 관리 흐름

  1. 이미지 만들기: Base Image + App Layer
  2. Docker Hub: 이미지 저장 및 공유
  3. 컨테이너 실행: 상태 보존 여부에 따라 분기

🔌 그 밖에 고려할 요소들

네트워킹과 볼륨

  • 컨테이너 간 통신 (TCP/IP)
  • 호스트와의 파일 공유

고급 기능

  • 네임스페이스, 이미지 레지스트리, 클린업 전략 등

✍️ 마무리

  • 지속적인 인도/배포는 빠른 피드백 루프를 만들고,
  • Docker와 같은 컨테이너 기술은 이를 경량화하고 효율화함
  • Jenkins + Docker + GitHub 조합은 가장 대표적인 CI/CD 스택
  • “코드 커밋 → 테스트 → 인수 테스트 → 배포”의 자동화를 구성하려면, 각 도구의 역할과 흐름을 이해하는 것이 핵심이다.

🐳 Docker + Apache 실습 기록: httpd 컨테이너 실행과 index.html 수정

이번 실습에서는 Docker를 사용해 Apache(httpd) 웹 서버 컨테이너를 실행하고, 컨테이너 내부의 index.html 파일을 직접 수정하는 과정을 수행했다. 정적 웹서버 환경 구성의 기초를 학습한 실습이다.

1. httpd 컨테이너 실행

docker run httpd
  • 컨테이너를 실행했지만 fully qualified domain name 경고 메시지가 나타남 (정상 동작에는 무관).
  • Apache 서버가 실행되고 로그 출력됨.

2. 컨테이너 내부 접속 및 DocumentRoot 확인

docker run -it httpd /bin/bash

grep DocumentRoot /usr/local/apache2/conf/httpd.conf

DocumentRoot "/usr/local/apache2/htdocs"
  • Apache가 정적 파일을 서빙하는 루트 디렉토리는 /usr/local/apache2/htdocs 임을 확인.

3. index.html 수정

cd /usr/local/apache2/htdocs
ls -l
cat index.html

<html><body><h1>My Page</h1></body></html>
  • 기본 index.html 파일을 확인하고 수정하려 했지만 vi 명령어는 미설치로 실패.
  • 파일 내용을 수동 편집하고자 했으나 편집 환경 미흡.

4. 컨테이너 종료 및 확인

exit

docker ps -a

CONTAINER ID   IMAGE     COMMAND               STATUS                      
5a237699c8d9   httpd     "httpd-foreground"    Exited (0) 22 seconds ago
1b4b4bbc7f70   httpd     "/bin/bash"           Exited (0) About a minute ago
2e1c52dc4ad2   httpd     "httpd-foreground"    Exited (0) 8 minutes ago
  • Exited 상태의 컨테이너들이 확인되며 정상 종료되었음을 알 수 있다.

관련 명령어 정리: docker run, docker exec, grep, cat, exit, docker ps -a
