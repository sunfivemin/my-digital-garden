# 📘 2025-07-08 TIL

# 🌐 GitHub 오픈소스 프로젝트 운영 정리

## 1. GitHub 오픈소스 문서 구조
#### ● 기본 문서
- https://license.md/: 라이선스 전문 (필수)

#### ● 추가 문서
- README.md: 프로젝트 개요, 사용법
- COPYRIGHT.txt: 저작권 명시
- NOTICE.txt: 라이선스 개요
- CONTRIBUTING.md: 기여 방법 설명
- CODE_OF_CONDUCT.md: 커뮤니티 참여 규범

 “LICENSE 파일이 최상위 디렉토리에 있어야 해당 라이선스가 적용됨”

---

## 2. GitHub에 라이선스 추가하기

- 저장소 생성 시 자동 포함 가능
- 기존 저장소: Add new file → LICENSE 선택
- GitHub Docs: [Adding a license](https://docs.github.com/en/)

---

## 3. 커뮤니티 건전성 체크리스트 (GitHub 기준)

- README.md
- LICENSE
- CODE_OF_CONDUCT.md
- CONTRIBUTING.md
- Security Policy
- Issue Template
- Pull Request Template

---

## 4. GitHub 프로젝트 참여 구조

### 1) Issue
- 기획, 버그, 개선, 요청 등 모든 활동에 대한 논의
- 상태: Open, Closed

### 2) Pull Request
- Branch 간 코드 반영 요청
- 리뷰 후 Merge

### 3) Discussion
- 이슈 외 토론용 채널
- ex) 기능 방향 논의, 커뮤니티 피드백

---

## 5. 추천 문서 작성 위치

```tsx
.github/
├── CODE_OF_CONDUCT.md
├── CONTRIBUTING.md
LICENSE
README.md
NOTICE.txt
```

---

## 6. 오픈소스 프로젝트에 라이선스를 넣는 이유

- 사용자는 안심하고 사용할 수 있고,
- 개발자는 보호받을 수 있음
- 기업/기관은 라이선스 미준수 시 책임 발생 가능

---

## 7. 결론
- 오픈소스는 공유를 전제로 하지만, **규칙이 있는 공유**입니다.
- GitHub 프로젝트를 공개할 때 반드시 **라이선스와 문서 구조**를 갖추어야 합니다.
- 커뮤니티에 기여하고 싶은 사람을 위한 환경을 만드는 것도 오픈소스의 일환입니다.
