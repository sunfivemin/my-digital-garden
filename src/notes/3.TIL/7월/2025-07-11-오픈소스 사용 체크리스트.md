# 🌍 오픈소스 기여부터 저자 경험까지: 기여가 커리어가 되는 흐름

## 🧭 시작하며

처음 오픈소스에 관심을 가졌을 때는 "어떻게 기여할 수 있을까?"라는 막연함이 컸다. 하지만 커리큘럼을 따라가며 개념, 라이선스, 기여 유형, 실습까지 해보니 오픈소스는 생각보다 친절한 세계였다. 특히 Airbnb의 `lottie-web` 프로젝트에 기여를 실습하며, 그동안 배운 내용을 체화할 수 있었다. 이번 글에서는 기여 여정부터 실제 포크 실습, 라이선스 이해, 그리고 저자가 되는 법까지 전반을 정리해본다.

## 🧪 실습: Airbnb의 `lottie-web` 포크 & 기여 흐름

> 💡 원본 저장소: [https://github.com/airbnb/lottie-web](https://github.com/airbnb/lottie-web)
1. **Fork**: 원본 저장소를 내 GitHub 계정으로 복사
2. **Clone**: 내 계정에 복사된 저장소를 로컬로 복제

```bash
git clone https://github.com/내아이디/lottie-web.git
```

3. **Upstream 설정**: 원본 저장소를 `upstream`으로 등록

```bash
git remote add upstream https://github.com/airbnb/lottie-web.git
```

4. **기여 브랜치 생성 & 작업**

```bash
git checkout -b fix/readme-typo
# 작업 → 커밋 → 푸시
git commit -m "fix: correct typo in README"
git push origin fix/readme-typo
```

5. **Pull Request 생성**: GitHub에서 compare & pull request 클릭 → 설명 작성 후 PR 생성
6. **리뷰 → 머지**: 리뷰가 승인되면 merge되며 기여 완료 🎉

## 🧠 오픈소스 기여 유형 & 동기

|유형|설명|
|---|---|
|버그 수정|오류 고치기, 재현 가능 케이스 정리|
|문서 보완|README, 가이드 문서 등 개선|
|기능 제안|Issue로 제안, PR로 구현|
|테스트 추가|기존 테스트 보완 또는 신규 작성|
|번역|다국어 지원, 오탈자 수정 등|

**왜 기여할까?**
- 코드 품질 향상 & 협업 경험
- 유명 프로젝트에 이름을 남기기
- 취업/포트폴리오 어필
- 실제 유저 피드백 반영 → 사용자 중심 개선

## 🔐 오픈소스 라이선스 이해 & 제안

### 오픈소스 라이선스가 없다면?

- 오픈소스가 **아님** → 자유롭게 사용·수정·배포 불가
- 기여하고 싶다면 **이슈 등록 or PR로 라이선스 제안** 가능

### 어떤 라이선스를 제안할까?

- `MIT`: 가장 단순하고 많이 사용됨. 누구나 사용 가능, 출처 표기만 하면 됨
- `Apache 2.0`: 기업/상용 목적에도 안전하게 사용 가능
- `GPL`: 파생 프로젝트까지 공개 요구 (강한 copyleft)

📌 **라이선스는 중간에 바뀔 수도 있다!** 단, 기존 기여자 동의가 필요함.

- 예: MongoDB → AGPL → SSPL
- 예: Elasticsearch → Apache → SSPL

## ✍️ 저자(Author)가 되면 좋은 이유

- 기능 구현 PR이 머지되지 않거나 방향성이 다를 경우, 프로젝트를 **fork**하여 독립적으로 운영 가능
- 오픈소스 기반으로 **나만의 유틸/툴/프로젝트 런칭** 가능
- 라이선스 포함된 상태에서 공개하면 누구든지 사용 가능

### 저자가 되는 방법 체크리스트 ✅

- `LICENSE` 파일: 라이선스 명시
- `README`: 소개, 사용법, 목적 명시
- `CONTRIBUTING.md`: 기여 방법 가이드 (선택사항)
- 이해하기 쉬운 코드 구조 & 이름

## 🎯 오픈소스 기여가 채용에 어필되는 이유

1. **협업 능력**: 코드 리뷰, 이슈 기반 토론
2. **문서력**: README, 가이드 문서 작성 → 비개발자와도 협업 가능
3. **코드 품질**: 기존 코드 분석, 리팩터링
4. **지속적인 개선 경험**: 블로그, 포트폴리오로 정리
5. **기획·설계 능력도 함께 보여줄 수 있음** → 다양한 직군으로의 어필 (예: 기획, QA, 기술문서 작성 등)

 ✅ 회사 입장에서는 오픈소스 기여 경험이 "자기주도적 문제 해결 능력"을 증명해주는 요소가 됨

### 개발 후
- 사용 모듈 목록 정리
- OSS 사용 기록 정리 및 보안 문서 제출
