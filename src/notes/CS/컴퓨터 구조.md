컴퓨터 내부의 원리를 파악해보자.
하드웨어와 소프트웨어로 구성되어 있다. 현재 컴퓨터 구조는 폰노이만 구조를 따른다. (CPU가 메모리 하나씩 읽어가는 구조)
4대 하드웨어 : CPU(중앙처리장치), Memery, Storage, Network

###  **컴퓨터 주요 구성 요소** 
**1. CPU**: 연산 - 산술, 논리 연산 / 제어 - 입출력 장치, 메모리, 연산 동작 제어
**2. Memory**: 주기억장치 - CPU 안에 있는 register, cache, DRAM 등 메모리 / 보조기억장치 - SSD, HDD 
**3. IO Devices (입출력 장치)** : 입력 장치 - 마우스, 키보드 / 출력 장치 - 모니터, 프린터, 스피커 / Network Card
▶ 세 가지로 이루어져있고 내부의 버스(BUS)로 IO Device에 데이터를 송수신하여 컴퓨터가 동작한다.

 
### **0(off)과 1(on) : 비트(bit - Binary Digit)** 
X와 Y에 대해 OR(논리합: 0+0=0, 0+1=1), AND(논리곱: 1x0=0, 1x1=1), NAND(AND의 반대), NOR(OR의 반대), XOR(하나만 참일 경우 참), NOT(부정)의 논리 연산을 정의한다.

### **가산기(Adder)**
이진수의 덧셈(Sum)과 올림자(Carry)을 구하는 논리 회로

**1. 반가산기 (Half Adder)**  
두 개의 비트를 더하여 합(sum)과 올림자(carry)를 구한다.  
반가산기는 한자리에 대해서 sum과 carry만 구할 수 있다.

![](https://blog.kakaocdn.net/dna/5OKjE/btrV6Dbt5ou/AAAAAAAAAAAAAAAAAAAAAD206F6BUReeiwI-4TbiKJ8p7t-Up0-vhw8-TT72RV4U/img.png?credential=yqXZFxpELC7KVnFOS48ylbz2pIh7yKj8&expires=1753973999&allow_ip=&allow_referer=&signature=SyPdff7zEaLadxOZ4mDfqVoCtk0%3D)

Sum : XOR 연산과 같은 결과
Carry :  AND 연산과 같은 결과 / 1+1일때만 올림자 1이 발생한다. (1+1 = 10)

**2. 전가산기 (Full Adder)**  
반가산기 원리를 이용해 여러 자리의 합을 계산하기 위한 것이 전가산기다.
전가산기는 반가산기 2개와 하나의 OR 게이트로 구현된다.
전가산기의 여러자리의 합을 통해 32비트 64비트를 계산할 수 있다.

### **오실레이터(Oscillator)** 
0과 1의 반복적인 시간 변화 신호를 생성하는 전자 회로
오실레이터의 신호는 디지털 로직 및 통신을 클럭으로 실행하는데 사용된다.
CPU가 2.5GHz일 때 속도를 빠르게 하려고 4GHz씩 주기(Cycle)을 높이는 것을 오버클럭이라 한다. 오버클럭 시 열을 식혀주는 장비를 같이 붙이는데 차라리 좋은 CPU를 사는게 효율적이다.

### **플립플롭(Flip-Flop)** 
1bit를 기억할 수 있는 조합논리회로로 이루어진 메모리로 데이터를 저장하고 삭제하는 기능을 가진다.
플립플롭이 여러개 모여있는 저장장치가 레지스터다. RS, JK, D, T 등 다양한 특성을 가진 플립플롭이 있다.

 
### **Latch** 
1 bit를 일시적으로 저장할 수 있는 메모리(D-type flip-flop) 이다.
8개 연결하여 8 bit latch를 구성할 수 있고 특정 latch만 선택하여 특정 주소를 읽고 쓸 수 있다.
selector와 decoder로 RAM(Random Access Memory)을 구성한다.
(삼성전자에서 64K DRAM를 세계 최초로 개발하여 메모리반도체 시장에서 정상을 차지했다.)

### **레지스터(Register)** 
누산기(Accumulator): CPU 내에서 연산의 처리 결과를 임시로 저장하는 레지스터
PC(Program Counter): 다음 실행할 명령어 주소를 가리키는 레지스터
IR(Instruction Register): 가장 최근에 인출한 명령어 보관 레지스터
MAR(Memory Address Register): CPU가 메모리 참조를 위해 데이터 주소를 임시적으로 저장 레지스터
MBR(Memory Buffer Register): CPU가 메모리로부터 읽으면 해당 데이터를 임시적으로 저장하는 레지스터

### **CPU 기본 실행 구조** 
1. 실행할 명령어를 Memory에서 읽어 CPU로 가져옴(Instruction Fetch) :
PC가 가리키는 주소를 MAR에 보냄 -> MAR에 적힌 주소를 읽어 MBR에 보냄 -> MBR에 있는 명령어를 IR에 저장 -> 다음 명령어를 가리키도록 PC 주소값 증가
2. 인출한 명령어에 포함된 데이터를 가져오고 명령어를 해독함(Instruction Decode)
3. 명령어 실행(Instruction Execution) :
MBR의 데이터와 누산기의 데이터로 연산 후 누산기에 저장
4. 실행결과를 저장(Write Back)
DMA(Direct Memory Access): CPU가 캐쉬까지는 데이터를 가져오는데 관여하지만 메모리, SSD에서 데이터 가져오는데 까지 관여하면 CPU의 활용도가 낮아진다. 이 때 DMA를 만들어 메모리, SSD에서 데이터를 관리하면 CPU는 이 시간을 명령실행에 더 쓸 수 있다.

CPU성능을 높이기 위해 하나의 작업에 필요한 일을 세부적으로 나누어서 동시에 다른 세부작업을 실행하는 기법.

### **CPU 명령어를 정의하는 전략** 
RISC(Reduced Instruction Set Computer) : 간단하고 적은 종류의 명령어를 조합해서 실행, ARM CPU(스마트폰, 임베드, IoT 기기)
CISC(Complex Instruction Set Computer) : 하나의 명령어 실행으로 많은 작업 수행 (복합 명령어 수행을 위해 CPU 로직 회로 복잡도 증가), INTEL CPU
